# 任务确认与证据底表

## 审读后再提问

先从任务书、模板、文件名、正文和元数据中寻找答案。只有下列信息缺失且会改变成稿时才询问：

1. 报告的使用场景和主要读者。
2. 研究对象、时间范围、篇幅和截止时间。
3. 多份统计文件冲突时，哪一份是主口径。
4. 是否署名、匿名、公开，是否需要参考文献、附录、Word 或 PDF。

把必要问题合并成一轮。不要问用户已经在材料中明确写过的内容。

## 证据状态

- 已确认：材料直接支持，可以按来源允许的范围写入。
- 待确认：材料缺失、口径不明或彼此冲突。询问用户，或在不影响核心结论时弱化处理。
- 合理解释：由多项材料推得。正文必须写成分析、可能原因或研究者判断，不能伪装成已发生事实。
- 禁用：无法核验、涉及隐私、统计口径错误，或用户明确要求删除。

## 允许写法

底表中的“允许写法”用于控制结论强度。例如：

- 原材料仅说明受访者选择比例时，写“在本次样本中”，不写“公众普遍认为”。
- 只有横断面相关结果时，写“二者存在关联”，不写“前者导致后者”。
- 只有团队计划时，写“团队拟开展”，不写“团队已完成”。
- 多份材料对日期说法不一时，先确认；无法确认且日期不是论证重点时，写成实际时间范围，不编造具体日。

## 冲突处理

用户指定的主数据文件优先。没有指定时，比较文件版本、更新时间、统计口径和样本说明。仍不能判断的事实进入待确认，不自行取平均，也不挑选更有利的数字。
